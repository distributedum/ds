Server dispatching

Changing the server or the pool restarts the run and replays the same number of ticks.

Callbacks

Halfway through its work, the handler sends a request to a client (a callback) and waits for the reply in the server's pending table. Each client runs the same middleware as the server: a reader, a writer with an outgoing queue, a pending table and, unless it handles callbacks in its reader, a work queue and pool. A callback takes 2 ticks to handle. Which handlers and which client apply from the tick on screen; how the client handles callbacks restarts the run.

Clients

Changing the thread mode or counts restarts the run and replays the same number of ticks. Pause acts from the tick on screen: a paused client runs no thread at all, so nothing reads its connection: think of a long GC pause or a breakpoint. You can also click a client in the drawing, or press 1 or 2.
